# 采集任务与打包下载任务完善计划

## 目标

让运维中心在页面刷新后仍能看到历史打包任务，并持续展示采集与打包任务的可操作状态；完成任务后能稳定下载，过期任务明确不可下载。

## 范围

- 为书籍打包任务增加有界、按更新时间倒序的列表读取链路。
- 运维页改为从服务端加载打包任务，而不是只记住当前页面创建的任务。
- 采集运行卡片补充待处理、进行中、失败、取消和剩余数量。
- 补充领域/服务/UI 回归测试，并同步交接与进度文档。

## 非目标

- 不引入 WebSocket、SignalR 或新的队列系统。
- 不改变现有采集控制状态机、打包格式或权限模型。
- 不为已失败的打包任务增加新的人工重试语义；现有 Worker 自动重试保持不变。

## 验收条件

1. `GET /api/v1/admin/packages?limit=N` 只返回受保护、有限数量的打包任务，按 `UpdatedAt` 新到旧排序。
2. 打包任务列表包含排队、运行、完成、失败、过期状态；完成且文件存在时提供下载入口。
3. 运维页刷新后可恢复历史打包任务，并能在轮询中更新状态；不会展示凭据、租约或正文内容。
4. 采集运行页展示总量、已完成、进行中、待处理、失败、取消和剩余数量，控制动作保持可用。
5. 受影响的 Unit、Architecture/Contract（如适用）、Release Build/Test、Docker/VM 运行验证和文档均有证据；未执行项明确标记。

## 风险与验证

- 列表读取可能暴露过多任务或敏感字段：使用固定上限、最小响应模型和既有 `OperationsRead` 权限。
- 页面轮询可能重复请求：复用现有 4 秒轮询并加单请求互斥，不引入后台连接。
- 任务状态与下载文件可能短暂不一致：继续以服务端 `Completed`、artifact 名称和受限文件存储为准。

## 增量切片

1. 仓储/服务列表契约与测试。
2. 受保护列表 API 与响应测试。
3. 运维页历史打包任务加载、状态展示和采集数量展示。
4. 全量验证、VM 源码构建/运行冒烟、文档和提交推送。

## 追加工作包：采集任务运维闭环

### 目标

让运维中心展示全部采集运行并按状态分类；失败运行可在受保护、带理由的操作中删除；采集来源可整体停用和恢复。

### 非目标

- 不删除成功、进行中或其他非失败采集运行。
- 不删除采集运行产生的书籍、章节、正文或审计事实。
- 不引入 WebSocket、无限制列表查询或新的来源适配器。

### 验收条件

1. 失败采集运行显示删除按钮；服务端仅接受失败状态，运行、子任务和死信明细在一个事务内清理，并保留审计记录。
2. 采集运行列表以稳定游标分批读取，页面自动汇总全部条目并按等待中、进行中、已暂停、已完成、失败、已停止、已取消分类。
3. 来源停用/恢复受现有 Source Operations 权限和理由约束，状态持久化；停用来源不会被地址解析、搜索、追更调度或 Worker 执行继续使用。
4. 受影响 Unit、Integration/Contract（适用时）、Release Build、VM 源码构建运行、浏览器页面和安全检查均有真实证据；未执行项明确记录。

### 增量切片

1. 失败运行删除：仓储原子清理、服务/API 审计和回归测试。
2. 采集运行稳定游标分页、页面全量汇总和状态分组。
3. 来源整体停用/恢复、运行时门控和运维页面。
4. 全量验证、文档同步、提交、CI 与 VM/浏览器验收。
