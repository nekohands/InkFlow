# InkFlow Architecture Overview

## 产品边界

InkFlow 是小说内容聚合、采集、阅读与开放协议分发平台。核心能力包括来源适配、任务调度、内容清洗与去重、统一书库、在线阅读、开放 API，以及阅读 3.0（Legado）兼容书源与订阅源。

## 运行时组件

1. `InkFlow.Api`：用户、书库、章节、搜索、阅读与 Legado API。
2. `InkFlow.Worker`：执行抓取、解析、清洗、去重与入库任务。
3. `InkFlow.Scheduler`：产生发现、更新检查和章节抓取任务。
4. PostgreSQL：系统事实数据与内容元数据。
5. Redis：缓存、锁以及第一阶段的分布式任务协调。

## 模块原则

采用 Modular Monolith。领域边界先在代码中隔离，部署层面保持较少进程；只有出现明确的伸缩、隔离或组织需求时才拆微服务。

## 内容模型

统一 `Book` 不直接绑定外部站点。同一本小说允许存在多个 `BookSource`；来源章节进入标准化管线后映射为平台章节/章节版本，以支持来源切换、补章、去重和质量评估。

## 爬虫边界

第三方站点实现 `ISourceAdapter`。核心采集逻辑不得使用域名 `if/else` 分支硬编码站点规则。

## Legado

阅读 3.0 面向稳定的 InkFlow API，而不是直接面向第三方站点。这样上游站点 DOM 或反爬变化只影响服务端 Adapter，不需要频繁更新用户已经导入的规则。
