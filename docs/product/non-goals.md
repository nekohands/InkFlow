# InkFlow 非目标与范围护栏

以下能力可能在未来有价值，但在其前置条件成熟前明确不做，避免核心链路被架构炫技或外围功能稀释。

## 当前明确非目标

- 不提前拆分细粒度微服务。
- 不提前引入 Kubernetes。
- 不提前建设 Multi-Region Active-Active。
- 不提前引入 Kafka 作为默认消息基础设施。
- 不提前建设复杂 AI 推荐系统。
- 不自研搜索引擎。
- 不建设论坛、私信、动态广场等重社交系统。
- 不自动破解 CAPTCHA。
- 不允许 Community Source 执行任意 C#、JavaScript、Shell、Process 或任意 Socket。
- 不提供任意 URL 公共代理接口。
- 不让 Redis 成为关键任务或业务事实的唯一数据来源。
- 不让 API 请求实时依赖第三方小说站抓取作为常规阅读路径。
- 不把第三方站点 URL 当作 InkFlow 的业务主键。
- 不把 EF Core Entity 直接暴露为公共 API Contract。
- 不在生产 API 启动时自动执行破坏性数据库迁移。
- 不因为内容 Hash 相同而绕过私人内容的授权边界。

## 何时可以重新评估

只有存在明确证据时才重新评估上述非目标，例如：

- 明确的性能瓶颈；
- 明确的团队边界；
- 明确的独立部署需求；
- 已验证的用户需求；
- 已验证的成本收益；
- 无法通过当前 Modular Monolith、Projection、缓存、索引或水平 Worker 扩展解决的问题。

任何突破本文件护栏的重大技术决策必须新增 ADR。
