# ADR 0014: 有界审计事实保留治理

- 状态：Accepted
- 日期：2026-08-29

## 背景

`audit.events` 是安全审计事实，普通应用路径必须保持追加式写入；但无限保留会使表和时间索引持续增长，也缺少可复核的清理边界。审计保留不能通过普通 CRUD 删除路径实现，也不能让一次历史积压清理长时间占满数据库。

## 决策

- 使用 `AuditRetentionOptions` 配置 `Audit:Retention`：默认保留 365 天，保留期最多 3650 天；每批最多 1000 行，每轮最多 100 批。
- `AuditRetentionService` 以 UTC 当前时间计算 `OccurredAt < cutoff`，按 `BatchSize` 和 `MaxBatchesPerRun` 双重上限调用存储 seam；单批未达到上限时提前结束。
- PostgreSQL 存储实现以 `(OccurredAt, Id)` 索引按时间顺序选取候选，事务内使用 `FOR UPDATE SKIP LOCKED` 分批删除。
- 数据库追加式触发器继续拒绝所有更新和普通删除；仅 retention 存储在同一事务设置 transaction-local 标记后，才允许本轮过期删除。Worker 启动延迟后每小时执行一次，不能通过 API 或用户输入触发任意删除。
- 生产环境仍须按法律、合同和安全事件需求选择实际保留天数，并补齐归档、恢复授权、删除审批和审计策略；本 ADR 只确定代码级安全边界，不宣称生产治理完成。

## 后果

正面结果是清理行为可配置、可限制、可回归，普通 SQL 删除和更新仍会被数据库拒绝，锁竞争不会阻塞追加写入。代价是保留期配置必须纳入部署治理，transaction-local 标记不是独立数据库角色；生产数据库角色和运维权限仍需遵循最小权限，并保留独立备份/归档策略。
