# ADR 0025：账户中心与敏感设置边界

- 状态：Accepted for 1.0 Release Candidate
- 日期：2026-09-02
- 范围：Reader / Identity / Personal Legado Token

## 背景

账户页已经承担登录、角色展示和退出操作。继续把书架入口、个人资料、密码和外部访问凭据堆在一张表里，会让
高频阅读入口与敏感账户操作混在一起，也会诱导实现没有验证链路的邮箱、头像或密码恢复功能。

## 决策

1. 账户中心按“账户信息 → 个人资料 → 账户安全 → 阅读器令牌 → 管理入口”分区；书架和阅读历史只保留在 Reader 顶部导航。
2. 1.0 只持久化一个可编辑的 `DisplayName`。登录邮箱、角色和账号状态是只读事实；邮箱变更必须等邮箱验证/恢复链路准备好后再开放。
3. 修改密码要求当前密码和新密码。服务端在 Identity 应用服务中完成校验，在同一 PostgreSQL 事务中更新密码并撤销用户全部 Web 会话；成功后当前浏览器也必须重新登录。
4. 阅读 3.0 令牌复用既有 Personal Legado Token 领域、API 和哈希存储。原文只在签发响应中返回一次，账户页不保存原文；列表和撤销必须以认证用户作为所有权边界。撤销是立即失效并删除记录的单一操作，不提供恢复，需要重新创建令牌。
5. 设备会话、邮箱验证、MFA/Passkey、账号恢复和开发者 API Key UI 延后到各自具备数据模型、通知/验证和安全验收条件的切片；头像上传由 [ADR 0026](0026-user-avatar-upload.md) 单独落地。

## 后果

- 账户页提供实际可用的资料和安全操作，同时保持页面与既有 API 的边界清晰。
- 修改密码会使所有 Web 设备退出，用户需要重新登录；这是安全优先的固定行为。
- 显示名称首字符仍是无头像时的安全回退；头像上传的格式、大小、所有权和私有缓存边界由 ADR 0026 单独约束。
- 延后项必须在拥有验证、审计、限流和恢复策略后再加入，不能用前端状态或本地存储替代服务端事实。

## 验证

- Identity 单元测试覆盖显示名称更新、当前密码校验、旧会话撤销和新密码登录。
- Reader HTML/runtime smoke 覆盖账户分区、令牌一次性展示标记、安全 DOM 写入、不重复展示阅读空间和头像上传入口；头像的持久化与格式边界另由 Identity 测试覆盖。
- Runtime 验收覆盖真实认证、资料更新、密码变更和 Personal Legado Token 创建/撤销；人工阅读 App 验收仍按既有清单单独执行。
